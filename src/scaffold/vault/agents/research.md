# Research and evidence

## Choose the depth from the question

Define the question, scope and intended use before collecting sources. For an
assignment, read its requirements through [academic-work.md](academic-work.md).
Use a direct verified source for a narrow factual question. For a literature
synthesis, compare independent relevant studies and seek disconfirming evidence.
For a systematic/scoping review, agree the review method and protocol first;
use the discipline's appropriate reporting guidance. PRISMA is a reporting
guideline, not proof of an exhaustive search or study quality.

Write down inclusion/exclusion criteria when they determine the synthesis:
population/context, constructs, study design, date range, language and relevance.
Explain filters that can exclude important evidence. Use the existing library and
course bibliography as seeds, then suitable scholarly databases, library access,
reference lists and forward citations. Web search helps discovery; it does not
replace discipline-specific database coverage in a promised systematic review.

## Search, verify and assess

For sustained research, keep one
[research log](../../00-system/templates/agent/research-log.md) with database/interface, execution
date, exact query, filters, screened candidates and inclusion/exclusion reasons.
Distinguish returned hits from sources actually opened and read. Record unavailable
databases and access barriers. Deduplicate by DOI or verified bibliographic
identity, and link preprints and published versions of the same study.

Open the source before making it evidence. Verify title, authors, year, venue,
DOI/URL and the passage supporting the specific claim. Never invent metadata,
citations, page numbers or quotations. Search snippets and AI summaries are leads.
Mark access precisely: `metadata_only`, `abstract_only`, `relevant_sections_read`
or `full_text_read`; a valid DOI does not imply the claim was verified.
When full text is unavailable, try authorized library/repository/author versions;
otherwise keep claims within the inspected abstract and name the limitation.

Assess fitness for the claim: design, sample/context, measurement, comparison,
effect and uncertainty where reported, limitations, funding/conflicts, publication
status and correction/retraction notices. Distinguish primary studies, syntheses,
standards and commentary. A review can establish the landscape; use primary
evidence for specific empirical claims where appropriate. Peer review and citation
counts are not substitutes for examining methods. Related papers using the same
dataset are not independent replications. Do not infer causality from association.

## Build the argument, not a pile of summaries

Keep a claim-to-evidence table for consequential syntheses: proposed claim,
source and locator, supporting or conflicting finding, limitations and judgment
(`supported`, `mixed`, `insufficient`). Reconcile disagreement by methods,
populations and definitions rather than majority vote. Explain how evidence
applies to the user's actual context and where extrapolation begins.

Use the existing reference manager as the bibliographic owner if one is configured.
Zotero is an optional fit, not an assumed installation or mandatory migration.
Keep stable verified item links or citekeys in Obsidian and analytical commentary
there; avoid manually maintaining a second bibliography. Without a manager, use
one source register and verified export metadata. Never edit a manager's database
directly. Reuse an existing source note instead of making one per search; the
[source-note template](../../00-system/templates/agent/source-note.md) is optional.

## Stop and resume honestly

A narrow lookup is done when the needed claim is verified. A narrative review is
done when the agreed scope has useful coverage, major conflicting evidence is
addressed, and remaining gaps are explicit. A systematic review is done only
against its declared protocol. A time limit or several repetitive searches can
end a work session, but cannot justify claiming exhaustiveness.

For an interruption, leave the existing research log with the exact query/step
reached, screened decisions, unopened candidates, unresolved claims and next
action. Preserve negative findings and access failures so the next session does
not repeat the search. Deliver only conclusions supported by inspected evidence.
