# Notes and learning

## Place knowledge where it will be used

Search the relevant course/session and linked notes before creating a note. Keep
session-specific material at its session, cross-session concepts at the course,
and general study rules in `Studium/`. Attachments belong in the existing
nearby `docs/` directory. Link exported artifacts from the working note. Reuse
`00-system/templates/termin.md` for a genuinely new session; let Study Manager
own event creation when it already supplies the session.

Keep existing frontmatter types, tags, headings and user wording. Patch the
smallest relevant section. Distinguish original lecture notes from later
clarifications, including date and source when correcting a substantive point.
Keep exam-specific teaching conventions and broader disciplinary qualifications
side by side when they differ. Do not silently replace the lecturer's convention.
Use vault-relative Obsidian links to existing targets; ordinary Markdown file
links are relative to their containing file. Resolve actual spelling and Unicode.

## Capture and consolidate

For a lecture or reading, capture the question or learning objective, essential
concepts, one worked example, unresolved questions and exact source locators.
Use a verbatim quote only with clear marking and a locator. Label paraphrases,
own deductions and agent additions. A citation remains necessary after translating
or paraphrasing. For PDFs distinguish PDF page index from printed page/slide number.
Verify visually when OCR affects a number, formula, table or quoted wording.

Consolidation should make the material usable: explain the reasoning, connect a
relevant earlier concept, and identify what the learner still cannot do. Prefer a
short explanation plus a useful example over rephrasing every slide. Create a
separate concept note only when it will support multiple sessions or assignments;
otherwise keep the explanation in place. Do not impose a new vault-wide taxonomy.

## Tutor, practise, then check transfer

In an interactive learning request, establish what the user already understands
with one focused question or problem. Let them attempt it, then give the smallest
useful hint, explanation and feedback. If the user explicitly requests a full
solution or summary, deliver it; offer a short self-check without withholding it.
Separate problem and solution so the user can attempt retrieval first.

Match practice to the assessment: explain concepts aloud, solve a new calculation,
trace a program, design an ER model, or defend a claim with evidence. Include at
least one changed example when judging transfer. State which answers or steps
are correct, the reason for errors, and one targeted next exercise.

Use spaced follow-up practice, adjusted to observed performance and the exam date.
An initial cadence such as next day, several days later and the following week is
a planning heuristic, not a validated personal optimum. After a failed attempt,
reduce the step size and revisit earlier; after reliable recall, increase the gap.
Do not create reminders unless requested. For flashcards, keep one retrievable
idea per card and include an answer explanation and source. Use problems for
skills that cannot be assessed with factual cards.

## Learning evidence

`vorbereitet` and `nachbereitet` are existing user/app fields. Preserve them unless
the user requests a status update or clearly authorizes updates during a study
session. Tie an authorized update to the user's report or observed activity; a
summary generated by the agent is not evidence that the user read or understood it.
Never infer attendance or exam readiness from these booleans.

Use an optional [learning-review note](../../00-system/templates/agent/learning-review.md)
for substantial practice: topic, attempted
task, assistance needed, observed result, remaining misconception and next review.
Keep `not_tested`, `with_help`, `independent` and `transfer_demonstrated` as evidence
labels in that note, not new mandatory app properties. A correct answer to one
item is evidence about that item, not mastery of the whole course.

Done: the requested note is in the right place with working links and traceable
additions; a learning session ends with observed ability and a specific next step.
